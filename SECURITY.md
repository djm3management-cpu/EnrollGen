# Security reporting

Report suspected vulnerabilities privately to **[OWNER MUST FILL IN: security contact address]**.
This is the single placeholder contact and must be completed before external use.

Include affected versions or commit IDs, reproduction steps using synthetic data,
impact and a safe way to reach you. Do not include credentials, customer records,
recordings or transcripts. Do not post sensitive reports in public issues or
attempt production exploitation. The owner should acknowledge receipt, arrange
secure follow-up and coordinate a fix and disclosure with the reporter.

If a credential may be exposed, revoke or rotate it at its issuing service and
review access logs. Removing a file from the current tree does not remove it from
Git history, forks or existing copies. The history scanner only reports findings;
it never rewrites history or performs rotation.
