## Access boundary and event shape

New migration: `157_evidence_access_and_minimization.sql`. Its complete copy is in bootstrap `sql/m157.sql`, after 156 and before the seal. The seal preserves the audit's restricted service ACL after its general service grants. Both manifest checksums and `catalog.expected.json` are regenerated from the empty in-process PostgreSQL build. No old migration is replayed against a live database.

`public.evidence_access_log` contains only:

| Field | Meaning |
|---|---|
| `id` | Database-generated event UUID. |
| `actor_id` | Verified Clerk subject for interactive work; an explicit service principal for background work. Capability redemption uses the stored issuer for ordinary tickets and `capability:compliance` for processor shares. An unrecognized bearer is `capability:unknown`, never a fabricated user. |
| `tenant_id` | Protected deployment tenant, independent of submitted tenant/role/actor fields. |
| `resource_type` | Reviewed table/resource classification. |
| `resource_id` | Application UUID, `collection` for a list, or SHA-256 of a non-UUID internal identifier. No paths, names, phone numbers, prompt text, or capability tokens are retained. Collection events identify the authorized scope, rather than retaining sensitive search filters. |
| `action` | `list`, `read`, `play`, `download`, `export`, `sign`, `ticket`, or `decrypt`. Playback/download grants carry their intended action; transport-level signing uses `sign`. |
| `result` | `allowed` or `denied`, describing the access decision. A later provider/stream failure does not retroactively change an allowed decision. |
| `occurred_at` | Database `clock_timestamp()`; clients supply no timestamp. |
| `grant_id` | Opaque UUID linking a request/grant to its stored ticket and subsequent media requests. It is not a bearer token or its hash. |

Only server code can insert directly. Browser reads require P0-2 `deployment_is_admin(tenant_id)` and the complete protected membership binding; ordinary members/managers see no trail. Browser insert/update/delete grants are absent. The service role has insert/select only. Statement triggers reject UPDATE, DELETE **and TRUNCATE**, including from the table owner and service code. Server code cannot silently repair an old event; it must append another event. A database operator who can disable triggers/change DDL remains outside the application-role threat boundary.

`telephony/src/lib/evidenceAudit.js` is shared by Netlify, telephony, and the independently packaged integrations image. It holds responses until their audit succeeds, checkpoints before handing off capabilities/media/exports, and shares the request grant across nested helpers. Server SDK factories install its query/RPC/storage proxy, so background jobs and new uses of the same protected tables cannot silently bypass it. Known evidence-returning RPCs are included. Browser reads use private-table, ownership-scoped audited database routines through `evidenceTransport.js`; PostgREST requests are POST because GET/HEAD transactions cannot insert audit rows. The routines retain P0-2 `deployment_row_visible` / `deployment_row_writable`, including manager read-only scope and admin authority. Both transcript-search signatures apply visibility **before** ordering/limiting. Content edits retain migration 153's exact field allowlists; denied content RPCs set a 403 response status while committing the denial event. The existing contact-wide unread-message action uses a narrow audited RPC, preserving its inbound/unread/assigned-contact filters. Direct protected table SELECT and direct browser storage signing are closed.

A list operation has one list event; an individual grant has one grant event; each media GET/HEAD/Range redemption has its own event. Intake collections additionally append one decrypt event per intake UUID and a contact-prefill decrypt event. These are distinct accesses, with a common request grant, rather than duplicate records for nested SDK calls. Failure to commit any required event prevents the associated data/grant/export from being released. Known denied resource/ownership/membership requests are logged after verified authentication. Feature-disabled surfaces still reject before authentication/database work, preserving P0-5. Malformed unauthenticated HTTP traffic is not attributed to an invented Clerk user.

Ordinary and compliance bearer URLs remain bearer capabilities until expiry. Redemption records link to their verified issuer/grant; a remote recipient's actual personal identity cannot be inferred from possession of a token. There is no false claim that the issuer personally watched each request. Local replay/copy/save-as of bytes already delivered to a browser, or subsequent opening of a downloaded PDF, cannot be observed by this server. App export actions are gated; arbitrary operating-system actions are outside the access trail. Continuous recipient session binding for processor shares requires an owner decision.

## Data reduced

* Incoming lead identity is consumed only by the contact writer. The intel JSON contains only `zip`, `county`, `state`, `lead_score`, `churn_risk`, `vendor_source`. Unknown/nested vendor fields, phone, MBI/SSN/payment data, and the second name/DOB/email copy are dropped. Intel string values pass the existing redactor. The earlier Paragon `publisher` disable check still runs even though publisher extras are not persisted. Contact identity remains available through its protected existing fields. The audit's mandatory removal of arbitrary vendor JSON necessarily removes those arbitrary fields from the payload editor; normal contact/plan/intake views and styling are preserved.
* The server LLM client recursively scrubs system/messages/static messages/tools and schemas, including serialized JSON tool arguments, for Medicare/SSN/phone/DOB/address/payment identifiers. Streaming and OpenAI fallback use the same scrubbed request. RTS ingestion and knowledge updates now use this shared client too; the retired processor and its shadow execution have been removed. Direct embedding boundaries scrub again. Structured identifier keys are removed even for unsupported scalar formats.
* Provider response bodies, arbitrary SQL/provider diagnostic prose/stacks/hints, shadow completion bodies and capability token hashes no longer enter the affected logs/reports. Machine outcomes/statuses remain. Lead failure responses are bounded constants. Existing delivery diagnostics retain their code/recipient-safe projection. Synthetic captured-log scans include provider and SQL errors containing names and identifiers.
* Recording and attachment storage URLs are not handed to the browser. Recording byte delivery is auditable on each request; attachment retrieval stays authenticated.
* Browser access to plaintext evidence copies is through audited P0-2 composites; contact plaintext/encryption blobs remain behind the existing protected contact RPCs. The original item did not rewrite historical values. Follow-up migration 159 re-encrypts only CRM delivery snapshots through their approved field allowlist; protected contact/intake records remain unchanged.

Regex scrubbing is **not** de-identification. Names, health discussion, uncommon/spoken identifier formats and arbitrary pasted free text require further review; raw speech necessarily reaches the STT/telephony processors. Synthetic tests prove the tested identifier formats do not leave the tested prompt boundaries, not that every possible utterance is anonymous.
