# Paragon vendor report and daily email

## Deploy

Apply `supabase/migrations/055_paragon_vendor_report.sql` and `057_paragon_vendor_report_proof.sql` to the production Supabase project, then deploy Netlify. The migrations create a hashed, revocable report token, access audit, database rate limit, narrow report query, and email send log. No token exists until an agency admin creates one.

## Report access

In **Agency Settings → Paragon state and carrier routing → Paragon vendor report link**, choose **Create report link**. Copy the full link once and send it to Paragon securely. **Rotate report link** immediately invalidates the previous link. **Revoke report link** disables access without replacing it.

The report URL is `/vendor/paragon?token=...`. The function authenticates and logs every GET, including failed attempts, and limits each IP to 30 requests per five minutes. Invalid, missing, revoked, and rate-limited tokens return 404. Browser and CSV responses are not cached and have a no-referrer policy. The page has no write controls.

The database report requires both the exact active `Paragon Media` publisher source and an accepted Paragon ping matched to the Twilio call. Source tagging alone is insufficient on the shared DID. The report returns only the eight approved fields. Times and date boundaries use `America/New_York`. Billable means duration of at least 90 seconds. Daily totals use $28 per billable call. Historical source-tagged calls without a matched ping are excluded because their vendor identity cannot be proven.

## Daily disposition email

Netlify schedules `paragon-daily-email` at 22:00 and 23:00 UTC and again at 15 and 30 minutes past those hours; the function runs only when the local New York time is 18:00–18:30. This covers daylight saving changes. The first attempt is at 18:00 ET; failed attempts retry at 18:15 and 18:30. A database claim and provider idempotency key avoid duplicate sends. A day with no calls is logged as `skipped` and sends no email. Every attempted send is logged in `paragon_report_email_log`, with status, count, time, and provider message ID or error code.

Sending uses Resend. Set the Netlify environment variable `RESEND_API_KEY` to a **sending-only** key for a verified `newgenhealthsolutions.com` domain. The sender is `reports@newgenhealthsolutions.com`, reply-to is `mike@newgenhealthsolutions.com`, and the recipient is `dispo@paragonmedia.io`. The attachment is a CSV generated by the same helper as the vendor download. If Resend is not configured, a day with calls records a failed attempt; it does not silently drop the report.

The `newgenhealthsolutions.com` domain was added to Resend with GoDaddy auto-configuration. The reported DNS records are CNAME `send`, CNAME `rsend`, and TXT `resend._domainkey`; do not replace them with generic manual records. Wait for Resend to show the domain as verified before the one-time test email.

`RESEND_API_KEY` is stored in Netlify for **enrollgen → Production → Functions** and is never committed or placed in a `VITE_` variable. The production deploy must be refreshed after changing the key. Send one controlled test to `mike@newgenhealthsolutions.com` once the domain is verified.

On 2026-10-01, a one-time dummy email from the production function to `mike@newgenhealthsolutions.com` was accepted by Resend (provider message ID `01a0f8b2-3b96-7ba3-86e6-6a9592c57a9a`). The temporary test endpoint was removed after the send. This confirms API acceptance; inbox delivery can be checked in Resend's email activity and Mike's inbox.
