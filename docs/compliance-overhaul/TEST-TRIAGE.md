## Customer audio and transcription failures, in plain English

- Authentication, stale-connection, speaker-label, interim-replacement and conference-handoff failures: the browser tests removed imports but never supplied the new recovery wrapper. They failed before processing audio. Updated fixtures now exercise that real wrapper with fake sockets and authorization responses.
- Disconnect recovery: capture should stay active during a brief outage. The fallback processor incorrectly stopped feeding audio while disconnected; this prevented the wrapper from reconnecting when speech resumed. Fixed and added a regression test.
- Speech-service rejection and terminal limits: rejection was swallowed and terminal closure never reached the hook, leaving capture resources active. Forward the error and terminal close, then release cloned media and report only bytes actually sent. Added a buffer-exhaustion regression test.
- Rendered dual-channel panel: its VM lacked the new registration/alert dependencies and inbound-call context. Updated the fixture; both speaker streams, interim replacements and ordered final speech remain checked.
- Server media tests: fake speech sockets were blocked by the new durable registration gate because fixtures did not inject that authorization. Added local doubles; replaced old timer-driven retries with speech-triggered recovery and tested configured retry/queue bounds and buffered backpressure drainage.
- Transcript dispatch tests: scoring now defaults to disabled. Enable only the injected dispatch fixture; transcription persistence remains independent.
- Coverage-related scoring failures: old fixtures had short calls or no customer/agent timeline. Complete fixtures now supply both channels across at least 95% of a 15-minute call. Incomplete evidence stays ungraded, and short/excluded calls cost zero tokens. No missing customer speech is fabricated.
