# Supervisor whisper

Local implementation on `pilot/release`: original Whisper work based on `8ee3b3b`, recording-safety follow-up based on `79018d7`. No push, deploy, hosted database, live call, provider API request, dependency addition, vendoring, real environment-file edit, historical migration edit, stylesheet edit or active-secret-exception change. Public provider documentation was read; all executed provider transports are stubs. Migration **168_supervisor_whisper.sql**, its verbatim bootstrap entry, checksums, catalog snapshot and routine inventory travel together.

## Admission and join

The existing Floor presents **Whisper** to protected managers within their explicit enrolled-agent scope and protected agency administrators. The connected call must have both original SIDs, no terminal attempt/canonical call, no pending wrap-up, an active current agent leg for an existing conference, and no conflicting operation lease. Ringing, upgrading, warm consultation, blind transfer, recovery, voicemail and ended conferences refuse admission. Ordinary agents, foreign organizations, missing/inactive bindings and empty manager scope cannot mint or redeem grants.

`POST /api/supervisor-floor` with `action: whisper` extends the existing Listen capability boundary. A random 256-bit capability has a 45-second lifetime; only its SHA-256 is stored. Existing grant rows now distinguish `listen` and `whisper`. The actor, verified Clerk session, tenant, enrolled agent, attempt and exact current canonical call are bound and independently rechecked by the phone server. Minting invalidates the actor's previous unused capabilities. Listen cannot redeem a whisper capability. The grant travels in an authenticated POST body, never a URL.

`POST /api/voice/whisper/token` consumes the capability transactionally. The existing per-actor session index applies across both Listen and Whisper. A second partial unique index allows one open whisper session per attempt; another permits one live supervisor participant per conference. An expired coach session retains its cap until provider cleanup finishes. Starting Whisper finishes that same supervisor's Listen relay on that call through the existing audited finish routine.

A direct outbound call first requests the existing mounted workspace checkpoint over the existing authenticated agent socket. Only the currently bound agent can acknowledge the opaque request after flushing that exact call's checkpoint. Missing acknowledgment fails after three seconds. Inbound calls already use the server transcript writer. The phone server then calls the existing `upgrade` and `connectOriginal` routines, under the existing `store.locked` operation lease. Their conversion bodies, parent/child checks, recording setup, child-first redirects, signed callbacks, stream handoff and recovery are retained. No hold, routing, reservation, availability, attribution or disposition action is dispatched by Whisper.

The existing Voice token issuer is shared with a restricted identity `coach_<session UUID without hyphens>`, with a 45-second token. The Voice SDK constructor and codecs are shared with the existing browser phone. The coach device never registers for inbound calls, opens an agent/transcript socket, announces presence or acquires availability. The token has no incoming grant. Its outgoing TwiML application connection can only redeem its own stored coach session; supplied telephone numbers and ordinary outbound operations are refused. Database constraints reserve the `coach_` namespace from roster, subject, availability and phone-presence identities.

The signed existing outgoing application webhook rechecks the stored session, authority and current call, acquires the existing conference lease and attaches a participant with role/speaker **supervisor**. The target must be the current connected agent, and a provider participant fetch must independently confirm that agent in the exact account and room. The browser receives only TwiML with a strict coach target; there is no ordinary-participant fallback.

## Provider controls and fail-closed checks

The provider contract comes from Twilio's [Conference TwiML reference](https://www.twilio.com/docs/voice/twiml/conference) and [Conference Participant resource](https://www.twilio.com/docs/voice/api/conference-participant-resource). `coach` targets an already connected agent Call SID; an invalid/disconnected target fails the Dial rather than authorizing a normal join. Join attributes are `muted=true`, `beep=false`, `startConferenceOnEnter=false`, `endConferenceOnExit=false`, `waitUrl=""` and `record=do-not-record`. The supervisor cannot start/end the room and is excluded from the application's surviving-person decision.

The join starts with both provider mute and local SDK mute. A local verification job starts after 250 ms, using a two-second provider timeout. It requires the exact account, conference, coach Call SID, `coaching=true`, exact `callSidToCoach`, connected status, both conference-start/end flags false and mute true. Missing fields, mismatches and provider errors remove the coach immediately. A user cannot enable Talk before that confirmation. Provider fetch serialization is tested against the installed Twilio SDK with a fake HTTP transport, avoiding invented SDK fields or methods.

Talk and Mute use only the supervisor participant resource. Each request renews current authority, holds the existing operation lease, verifies coaching, commits its administrator authorization record, reasserts `coaching=true` and the same target alongside the mute update, then verifies provider state again. Any audit, provider or confirmation failure removes the coach. Mute silences the local microphone before its request; Talk unmutes locally only after server success. No control offers customer speech or removal of coaching mode.

Renewal uses a fresh browser JWT every three seconds, current protected membership/scope, the existing actor-wide lock diagnostics, exact call/agent continuity and the deployment maximum. Database leases last eight seconds; independent browser and phone-server watchdogs last at most six seconds. The server caches only its known coach SID/session binding so a database outage cannot prevent a direct provider hangup attempt. Cleanup failures remain durable, occupy their caps, emit structured diagnostics and retry; coach audit/reconciliation failures do not block ordinary End Call or the existing conference recovery; a total provider outage cannot be made to guarantee instantaneous physical hangup.

Call completion, coached-agent departure, explicit Stop, lock/session expiration, revoked authority and maximum duration remove the coach. Warm and blind transfer controls remove it before dialing or placing the customer into a private consultation. If removal cannot be established, that private transition is refused. Ordinary Hold and Add Person keep the coach private. The existing conference recovery sweep checks stranded supervisor legs. Cleanup remains available for durable coach sessions after admission switches are disabled, without mounting coach HTTP routes or enabling new sessions.

Conversion refusal before preparation leaves the original call and participant tables unchanged. Provider failures during the existing converter never add a supervisor. Once the converter has prepared original participants or partially applied provider effects, its existing durable recovery remains authoritative. There is no new compensating redirect or purported distributed rollback. Exact audio continuity and restoration after an ambiguous/partial provider failure cannot be proven locally; the unchanged converter can finish an already prepared conversion during recovery.

## Existing conference behavior

Supervisor participants are filtered out of the agent-facing participant list, Add Person capacity, Leave Call's other-connected-person check and conference survival/voicemail decisions. Departure/join callbacks for them do not release agents, complete transfers, change ownership or emit an ordinary-person conference event. They have no agent slug, telephone number, reservation or presence. SQL attribution transfer explicitly rejects the role. Full-call cleanup can still terminate every leg.

The media routine returns immediately for this role. Database isolation checks prohibit stream generations/SIDs and recording SIDs, and media-lease, transcript-persistence, recording-enqueue and transfer routines independently reject it. Signed media tokens accept only the three original speech roles. The supervisor gets no media stream, speech connection, transcript segment, score or AI-coaching input of its own.

A whisper-only conversion preserves the agent's existing controls/display, apart from a small `Whisper · <supervisor name>` indicator. The existing conference participant panel stays hidden until the agent invokes an ordinary conference action. Once an agent chooses Hold or Add Person, its existing interface convention applies. The Floor reuses its poll, monotonic timers, lock/identity/visibility cleanup and existing theme tokens. No descriptive helper copy, new style rules, heavier font weights or new card pattern was added.

## Recording answer

**The agent-leg recording can contain supervisor speech. Marked calls now use only the verified customer-leg recording for outside audio and recording-to-text.** Internal authorized playback and individual source downloads retain their original behavior. The call keeps its small **Whisper** recording marker permanently, after Stop and after admission switches are disabled.

This source choice is confirmed from code and the provider's published audio-routing contract, rather than a telephone measurement. `telephony/src/conferenceCalling.js` starts a **Call** recording on each original participant's exact Call SID, before redirecting either leg, with `recordingChannels=dual` and `recordingTrack=both`. These are not whole-conference recordings. Twilio's [single-side recording guide](https://www.twilio.com/docs/voice/tutorials/how-record-single-side-call) and [Recording resource](https://www.twilio.com/docs/voice/api/recording) define inbound audio as speech received from that call endpoint, outbound audio as audio generated toward it, and dual/both as separate tracks. On the customer's per-call recording, channel 0 is customer speech and channel 1 is what the customer hears, for inbound and outbound calls alike. The [Participant resource](https://www.twilio.com/docs/voice/api/conference-participant-resource) specifies that only the coached participant hears the coach; existing join/control checks bind that target to the agent. Thus the customer leg excludes digitally routed supervisor speech, while the agent's outbound track can contain it. Physical loudspeaker feedback or a person repeating a coach's words is outside that routing guarantee; headset isolation and the listening acceptance steps below remain necessary.

Forward migration **169_whisper_recording_safety.sql** adds the service-only customer-source selector, permanent-marker preservation, held-upload/remediation routines and a narrow customer-leg exception to the existing automatic recovery admission. Its bootstrap copy, checksums, catalog snapshot and operator inventory are regenerated together. Earlier migrations and recording start/stop/storage behavior are unchanged.

The selector requires matching tenant/canonical call, the customer participant's exact Call SID **and** Recording SID, `StartCallRecordingAPI`, completed status, two channels, positive duration and no pending deletion. It never chooses a Dial/legacy, agent, third-party, whole-conference or merged artifact for a marked call. The existing `telephony/src/lib/whisperRecording.js` boundary is shared by the existing paths, independently of feature switches.

| Outside path | Marked-call behavior |
|---|---|
| Conversely automatic/manual selection and playability probes | Probe only the attributed customer MP3. Missing or provider-absent customer audio holds the call. |
| Conversely reviewer POST and admin WAV/MP3 shares | Mint only customer-recording capabilities, even if the old queue/UI selected the agent leg. Revalidate every GET/HEAD/Range redemption; reject an older agent ticket before any provider/media request. |
| SunFire IX carrier registration, streaming PUT, checkpoints and finalize | Register/upload only customer-leg audio. Validate saved registrations before resuming; a saved agent-containing registration is held, never uploaded or finalized. It requires provider remediation rather than an unsafe override. |
| Vendor report pages, CSVs and daily report emails | Existing explicit projections contain no recording bytes or recording links. No source is added. |
| Vendor disposition postbacks, availability/operational webhooks, GHL intake and legacy post-call webhooks | Existing allowlists contain no recording bytes or recording links. No source is added. |
| Exported consumer audit packet | The packet still embeds no audio. Exclude marked agent/legacy recording references and hashes before file hashing/PDF rendering; include only customer recording evidence. Hold the export if its customer source is unavailable or awaiting release. |
| Download merged WAV from either in-app player | Build the downloadable WAV only from the manifest's verified customer IDs. Hold intervals never select agent/private audio for this download. Internal merged playback continues using its existing source-selection rules. |
| Batch transcription, recording-gap recovery, intelligence backfill | Read only the customer recording/capability or cropped customer WAV. Assign speakers by channel, not diarized speaker IDs. Agent-source requests fail before reading audio or contacting speech providers. Old transcription tickets are rechecked at redemption. |
| Call-log CSV, session PDF/clipboard, office Nextcloud transcript/summary sync and existing model consumers | No recording bytes/links are included in these exports. Transcript/summary processing retains its existing isolated live inputs; newly restored recording-to-text uses the customer leg. |

No marked-call audio path falls back to the agent leg. Calls without the permanent marker retain their original upload selection, grant, playback, download and transcription behavior.

### Held state and release

When there is no usable customer recording, the existing call metadata records a durable upload hold. The existing operational alert state/history/delivery queue raises `whisper_upload_held`, deduplicated by opaque call hash; repeated attempts do not raise duplicate active alerts. The evaluator retains the condition across restarts. Existing structured worker diagnostics keep only IDs and fixed reason codes.

The existing **Compliance Uploads** status panel shows **Held**, the call reference and **Awaiting customer recording**. Once an eligible customer recording arrives, the same panel offers **Choose customer recording**. Only a protected agency administrator can release the hold by selecting that recording. SQL independently rechecks authority, tenant and exact customer attribution and commits both administrator and evidence-access records before release. Arrival alone, an ordinary Retry, another role, an agent ID, or disabling Whisper cannot release it. Held reviewer jobs stay outside automatic retries; IX uses its existing needs-attention state. Release requeues the held jobs through the existing queues. An incompatible saved carrier registration remains held pending provider remediation.

The blanket recording-to-text refusal is removed only for the verified customer path. Gap recovery retains existing approval, cost/day/range limits, single-pass reservation, durable request IDs and persistence. It uses the provider recording start as its timeline offset and refuses gaps outside customer-recording coverage; it never fills missing earlier time from an agent artifact. Batch/backfill channel 0 maps to customer and channel 1 to agent/shared customer-audible speech. A shared outbound conference mix cannot distinguish additional customer-audible third parties from the agent channel.

## Audit, history and retention

Admission inserts exactly one `supervisor_whisper` evidence `play` event and one `supervisor_whisper_start` administrator record in the same transaction as grant consumption and session creation. Either log failure rolls everything back and releases no token/join. The start is an **authorized attempt**, with the original server time and supervisor/agent/call bindings, not a false assertion of provider acceptance. Failed conversion/join attempts remain identifiable in history with an end.

Talk and Mute append `supervisor_whisper_talk` / `supervisor_whisper_mute` records with database timestamps before dispatch. Repeated identical state requests do not duplicate transition records. End appends `supervisor_whisper_end` in both trails and saves end time, duration and accumulated talk seconds. Retry is idempotent. These times measure authorized talk windows; provider/network latency can differ from the physical microphone interval. End-audit failure retains the session for reconciliation after the provider leg has been stopped. Existing append-only trails, security events, structured logger and alert pipeline are reused.

Protected admins see both modes in **Listen history**, with mode and total talk time. Managers/agents cannot read the list. Lifecycle uses its own `whisper` event, fixed summary **Supervisor whispered to agent**, recorded supervisor as staff and the session reference. The existing audit packet evidence index includes it with a non-file checksum of `not available`. No completeness check is added. The existing audit retention class and immutable anchors apply to sessions, and the existing operational class applies to ephemeral grants. No audio or transcript is stored in either.

## Limits and switches

`SUPERVISOR_WHISPER_ENABLED` defaults off in both application and phone server through the existing strict parser. Only exact `true` enables it, and it requires **both** `SUPERVISOR_FLOOR_ENABLED=true` and `CONFERENCE_CALLING_ENABLED=true`. Listen is independent. With any prerequisite absent, there is no Whisper tile action, grant redemption, coach token HTTP route or control/checkpoint route. Existing normal conference TwiML and normal token grants retain their values. Previously created coach legs still have removal/recovery, and retained historical evidence and recording-safety restrictions do not disappear.

For a separately authorized staging environment, apply reviewed migrations 168 and 169 after 167 (or use the checksummed fresh-install bootstrap), preserve the existing protected bindings and provider application/signature configuration, then set the three switches consistently on application and phone server. No actual environment was edited or enabled here.

`DEPLOYMENT_PROFILE_JSON.supervisorWhisper` accepts only `{"maxSeconds":1800}`, with a valid range of 1–7,200 seconds. Database caps are one coach per call and one call per supervisor across sessions/processes. Existing `supervisorListen` admission limits cover minting/redemption (six/minute by default); the existing admission parser/counters add `supervisorWhisper` for renewal/controls/checkpoint acknowledgment (60/minute by default). Stop is always permitted after authorization, even after admission exhaustion. Floor polling keeps its existing allowance. The existing single-replica telephony requirement and operation-lease limits remain.

## Three-phone staging telephone script

This script is documentation only and was **not executed**. Use a separately authorized isolated staging account/database and consenting testers. Prepare **three physical test phones**: Phone 1 customer, Phone 2 third party, Phone 3 transfer destination. The original agent and supervisor additionally use their existing browser phones with headsets, separate rooms and no loudspeaker feedback. A second enrolled browser agent can replace Phone 3 for the internal handoff variant. Use distinct spoken markers and have the customer and third-party testers independently record which markers they actually hear.

1. With all three switches off, place inbound and outbound baseline calls with Phone 1. Confirm ordinary ringing, answer, hold/transfer controls, transcripts, recording and disposition. Confirm no Whisper action/routes. Repeat with Whisper true but each prerequisite individually false.
2. Enable all three in staging. Confirm an in-team manager and admin see Whisper only for a connected eligible call; another team and an ordinary agent cannot join. Attempt ringing, wrap-up, blind-transfer and operation-lock cases. Confirm plain failure and normal caller conversation. Check provider account coaching entitlement/error handling before proceeding.
3. On a direct inbound call, say customer/agent baseline markers. Start Whisper while the supervisor's mic has continuous deliberate speech. Phone 1 must hear no joining/leaving tone, announcement, supervisor audio or other join signal. Confirm provider coaching and target SID, initial mute and the agent-name indicator. The supervisor hears the call. Enable Talk: only the agent hears the supervisor marker. Mute: the agent no longer hears it. Stop: Phone 1 and agent continue. Repeat outbound, including the existing transcript checkpoint.
4. **Hold:** start Whisper and Talk, hold Phone 1 using the existing control, speak distinct supervisor/agent markers, mute/resume and stop. Phone 1 hears only its expected hold state, never the coach. On resume, only the agent hears a new Talk marker. Repeat joins and exits while held. Inspect individual recordings and internal merged playback; expect coach markers in agent-track/held playback and none in inbound-only transcripts. Customer-only merged downloads must exclude those markers.
5. **Three-way:** add Phone 2 with the existing Add Person control before joining and again while Whisper is active. Phone 1 and Phone 2 must independently confirm they hear each other/agent but never the supervisor in muted, Talk, Mute, hold/resume and supervisor-stop states. Confirm no Add Person capacity/Leave Call eligibility is supplied by the coach. Remove Phone 2 and verify the original conversation survives.
6. **Warm transfer:** with Whisper active and Talk enabled, initiate Warm Transfer to Phone 3. Confirm the supervisor disconnects **before** customer hold/private consultation begins. Neither the supervisor nor Phone 1 hears the private consultation. Phone 3 never hears a coach marker. Complete, cancel and no-answer variants retain the existing behavior. Whisper must remain unavailable during consultation; after completion a new eligible join targets the actual current agent leg. Repeat an internal warm handoff with another enrolled browser agent and confirm disposition/ownership are unchanged by Whisper.
7. **Blind transfer:** while coaching, initiate Blind Transfer to Phone 3. Confirm coach removal before the original agent leaves, and no supervisor speech reaches either phone. Repeat answered, unanswered, online-agent return and voicemail fallback variants. A coach never keeps an otherwise empty customer room alive.
8. Repeat Talk/Mute/Stop while locking/unlocking, expiring the supervisor's session, revoking scope, ending the agent leg, ending Phone 1 and reaching a short staging `maxSeconds`. Kill/restart the staging phone process to exercise the existing recovery sweep. Confirm no stranded coach, no reservation/availability change and continued original conversation wherever the original call itself remains live.
9. In staging's fault-injection transport, fail capability audit, conversion lookup/stream/recording/redirect, target lookup, coach confirmation, Talk/Mute update and cleanup responses one step at a time. An unconfirmed coach never gets Talk. A failed cleanup blocks private consultation and is retried; the customer never hears supervisor markers. Retain only safe IDs/codes and reconcile ambiguous provider effects.
10. Inspect provider resources, live transcripts and saved scores/coaching: no supervisor stream, recording, speech socket, transcript segment or new speech attribution. Verify original recording behavior and the documented internal agent-track exposure. IX/reviewer media and merged downloads must use only the customer source; batch/gap/backfill must succeed on that source with channel labels, and agent-source requests must fail before speech-provider dispatch. Inspect the two start logs, timed Talk/Mute/end records, duration/talk total, admin Listen history, lifecycle event and packet index.

11. **Prove customer recording isolation by ear:** repeat inbound and outbound calls with headsets in separate rooms. Before conversion, say distinct customer/agent markers. During Talk, say an unmistakable supervisor-only phrase repeatedly while the agent remains silent. Repeat while the customer is held, after resume, after Mute, after Stop, and with all admission switches subsequently off. End the call and use service-owned participant/recording attribution to identify the exact customer and agent WAVs. Listen to **each channel separately**, not just the stereo mix: customer channel 0 must contain customer markers; channel 1 must contain only what Phone 1 actually heard (agent/shared speech or hold audio). Neither customer channel may contain any supervisor-only phrase. The agent WAV should contain the phrase during Talk as a positive control. Retain only safe call/recording IDs and the acceptance result.
12. Download the merged WAV from both the Recording tab and transcript player. Listen through every Talk, hold and stopped interval; supervisor-only phrases must be absent. Compare internal merged playback, where the existing held agent source may contain them. Confirm the small Whisper marker remains after Stop and switches off. In isolated staging with provider stubs or specifically authorized test recipients, verify reviewer and IX source IDs are the customer Recording SID and their decoded audio matches it. Inspect exported audit packet references/checksums for only the customer source. Vendor reports/webhooks must still omit recording fields entirely.
13. Withhold the customer callback/source in the staging fault-injection transport. Request reviewer/carrier/export work: confirm Held in Compliance Uploads and one operational alert across repeated attempts. Retry and choose the agent artifact using every available role; none may release/send it. Restore the genuine customer source: the hold must remain until a protected admin selects it. Then confirm the normal queues resume. Batch transcription/gap/backfill may process the customer source only; verify channel speaker labels and an agent-source refusal before any speech request. A gap before customer recording start must stay incomplete. Retain unverified results as failed acceptance, not as proof of clean audio.

Do not claim telephone acceptance until every customer/third-party tester confirms silence in every state, source recordings are checked, and partial-conversion/recovery continuity is accepted. A provider outage or acoustic coupling is not something synthetic tests can certify away.
